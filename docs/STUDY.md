# 공부할 것 (우선순위 순)

> 프로젝트 자체에 대한 설명은 `PROJECT_OVERVIEW.md`를 참고한다. 이 문서는 프로젝트를 만들면서 익혀야 할 내용만 모았다.

**공부 방식:** 강의보다 작은 실험 반복. 각 단계마다 "curl/Postman으로 API 한 번 호출 → 백엔드 엔드포인트로 감싸기 → 화면 연결" 순서로 진행한다.

---

## 1. LLM API 기본

우리 서비스에서 AI는 **백엔드가 OpenAI/Gemini 서버에 HTTP 요청을 보내고 답을 받는 것**이다. 아래 네 가지와 키 관리 원칙을 알면 된다.

### 1-1. 요청/응답 구조
요청에 모델 이름과 메시지 목록을 담아 보내면, 응답으로 생성된 텍스트가 돌아온다. Spring에서는 이 JSON을 만들어 보내고 응답을 파싱하는 작업이다.

```json
{
  "model": "모델이름",
  "messages": [
    { "role": "system", "content": "너는 일본어 퀴즈 출제자야. JSON으로만 답해." },
    { "role": "user",   "content": "핵심 문장: 駅はどこですか ..." }
  ],
  "temperature": 0.7
}
```

### 1-2. system / user 프롬프트
- `system`: AI의 역할과 규칙을 정하는 고정 지시문 (예: "반드시 JSON으로만 답하라", "정답은 제공된 핵심 문장에 근거해야 한다")
- `user`: 그때그때 바뀌는 재료 (핵심 문장, 스토리 상황, 퀴즈 유형)
- 우리 프로젝트에서는 system에 규칙을, user에 DB에서 꺼낸 문장을 넣는다.

### 1-3. temperature
답변의 무작위성을 조절하는 값이다. 낮으면 매번 비슷하고 안정적이고, 높으면 다양하지만 형식이 틀어질 위험이 커진다. 퀴즈는 JSON 형식이 깨지면 안 되므로 낮은 값에서 시작해 실험한다.

### 1-4. 토큰과 비용
AI는 글자 수가 아니라 **토큰** 단위로 요금을 받고, 보낸 프롬프트와 받은 답변 둘 다 계산된다. 프롬프트를 불필요하게 길게 쓰지 않는 것이 중요하고, 퀴즈를 DB에 저장해 재사용하는 2안이 비용을 줄이는 이유도 여기에 있다.

### 1-5. API 키는 백엔드에서만
키는 곧 결제 수단이다. 프론트 코드에 키가 들어가면 누구나 브라우저 개발자도구에서 꺼내 쓸 수 있고 그 비용이 내게 청구된다. 프론트는 우리 백엔드만 호출하고, 키는 `.env`에서 백엔드로만 읽어 들인다.

## 2. 구조화된 출력 (Structured Output)

- OpenAI/Gemini 공식 문서를 참고한다.
- JSON 스키마로 AI의 출력 형식을 강제한다.

---

## 3. 프롬프트 작성

- 대상 문장, 상황, 수준, 출력 형식, 예시 1~2개를 넣는 연습을 한다.
- 같은 프롬프트를 10번 돌려서 결과를 비교해 본다.

---

## 4. 음성 파이프라인

- `MediaRecorder` 녹음 (Chrome은 webm, Safari는 mp4인 경우가 많음)
- HTTPS 필요 (localhost는 예외)
- `FormData` 업로드
- STT 언어 지정
- TTS 결과 반환
- STT → LLM → TTS 3단계 직렬이라 응답에 수 초가 걸리므로 **로딩 UI를 미리 설계**한다.

## 5. 운영 문제

- 호출 실패 시 대체(fallback) 퀴즈
- 사용량 제한
- 비용 상한 설정
